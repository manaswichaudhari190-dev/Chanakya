Transform Procurement Requirements into Evidence-Backed Standards Intelligence.

CHANAKYA parses complex procurement requirement texts, extracts atomic technical parameters, retrieves and reranks applicable Indian Standards, detects outdated references, and enforces proof closure before recommending compliance clauses.

Core Product Philosophy: From Relevance to Proof

Four mandatory compliance conditions enforced before any standard recommendation becomes actionable.

🎯

Coverage Mapping

Maps every structured requirement atom (dimension, material, use-case) to at least one verified Indian Standard record.

📅

Temporal Gate

Validates standard edition currency against tender dates. Automatically rejects superseded or withdrawn specifications.

🔒

Proof Closure

Hard Invariant: No Proof → No Actionable Recommendation. Requires evidence nodes to close completely.

⚖️

Minimal Set (MSSS)

Determines the smallest sufficient set of standards to satisfy all procurement constraints without inflating tender scopes.

System Architecture & Data Provenance

Overview of the CHANAKYA pipeline stages, technical components, and prototype boundaries.

Pipeline Architecture Invariants
  • Hard Invariant: No proof, no actionable recommendation.
  • ETOG: Evidence-Typed Ontology Graph for relationship validation.
  • NCS: Normative Closure Scoring to verify complete requirement coverage.
  • MSSS: Minimal Sufficient Standard Set to prevent bloated specifications.
  • CNT: Coverage Necessity Typing (Essential vs Conditional vs Test Method).
  • Temporal Gate: Enforces version validity based on tender issue date.
Simulation Boundary Notice

This prototype is designed for SIH 2026 presentation and evaluation. It intentionally simulates vector search, embedding models, OCR, and external BIS API calls using deterministic local fixtures in data/demo_data.json.
